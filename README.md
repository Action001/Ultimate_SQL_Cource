# Описание учебной базы данных KINO (Video Service DB)

Данная база данных моделирует работу онлайн-кинотеатра (аналог Netflix, Kinopoisk, IVI). Она спроектирована для обучения SQL: от простых выборок до разработки сложной бизнес-логики (хранимые процедуры, триггеры, оконные функции).

## Быстрый старт (Установка)

### Вариант 1. Локальная установка
Перед запуском скриптов `KINO_MSSQL.sql` или `KINO_Postgre.sql` убедитесь, что вы создали пустую базу данных.

**Рекомендуемые клиенты (GUI):**
*   Для **MS SQL Server**: [SQL Server Management Studio (SSMS)](https://learn.microsoft.com/en-us/sql/ssms/download-sql-server-management-studio-ssms) — официальный и самый мощный инструмент. Альтернатива: Azure Data Studio.
*   Для **PostgreSQL**: [DBeaver Community](https://dbeaver.io/download/) (универсальный, очень популярный) или [pgAdmin 4](https://www.pgadmin.org/).

**Инструкция по созданию базы:**

**Для MS SQL Server:**
```sql
CREATE DATABASE KINO;
GO
USE KINO;
GO
-- Теперь запускайте содержимое файла KINO_MSSQL.sql
```

**Для PostgreSQL:**
```sql
CREATE DATABASE kino_db;
-- Подключитесь к этой базе и запустите содержимое KINO_Postgre.sql
```

### Вариант 2. Docker (Рекомендуемый для сервера)
Этот способ позволяет одной командой запустить MS SQL Server и PostgreSQL в изолированных контейнерах, не устанавливая их в систему.

1.  Установите Docker Desktop.
2.  Запустите в папке проекта:
    ```bash
    docker-compose up -d
    ```
3.  Теперь базы данных доступны на вашем компьютере (`localhost`).

## Подключение и начало работы

Независимо от того, как вы установили базы (локально или через Docker), вам понадобится **SQL-клиент** — программа для написания запросов.

### 1. Установка SQL-клиента
Рекомендуем установить один из следующих бесплатных инструментов:
*   **[DBeaver Community](https://dbeaver.io/download/)** (Рекомендуется) — универсальный, поддерживает и MSSQL, и Postgres.
*   **[SQL Server Management Studio (SSMS)](https://learn.microsoft.com/en-us/sql/ssms/download-sql-server-management-studio-ssms)** — только для MS SQL. Стандарт индустрии.
*   **[pgAdmin 4](https://www.pgadmin.org/)** — только для PostgreSQL.

### 2. Настройка подключения

Откройте ваш SQL-клиент и создайте новое подключение.

#### Подключение к MS SQL Server
*   **Host (Server):** `localhost` (или `localhost, 1433`)
*   **Authentication:** SQL Server Authentication
*   **User (Login):** `sa`
*   **Password:** `SuperStrongPwd123!`
*   **Trust Server Certificate:** ✅ (Обязательно поставьте галочку в настройках драйвера/SSL, иначе подключение не пройдет).

#### Подключение к PostgreSQL
*   **Host:** `localhost`
*   **Port:** `5432`
*   **Database:** `kino_db` (создается автоматически в Docker) или `postgres`
*   **User:** `postgres`
*   **Password:** `postgres`

### 3. Заливка данных
После подключения откройте файл скрипта (`KINO_MSSQL.sql` или `KINO_Postgre.sql`) в вашем клиенте и выполните его (Execute Script).
*   Не забудьте сначала убедиться, что БД создана и вы не находитесь в master

## 1. Назначение и функциональность

База данных позволяет реализовать полный цикл работы видеосервиса:

*   **Управление контентом:** Хранение каталога фильмов с привязкой к жанрам, рейтингам и возрастным ограничениям.
*   **Учет пользователей:** Регистрация пользователей, хранение их персональных данных, баланса и истории активности (с учетом часовых поясов).
*   **Биллинг и подписки:** Управление тарифными планами (Basic, Premium, Family), отслеживание статусов подписок и история платежей.
*   **Аналитика просмотров:** Сбор данных о том, кто, что, когда и на каком устройстве смотрел.
*   **Социальная активность:** Хранение пользовательских оценок и текстовых отзывов к фильмам.
*   **Безопасность и Аудит:** Логирование критически важных изменений (например, изменений баланса) для анализа инцидентов.

## 2. Структура Базы Данных

БД состоит из 8 основных таблиц.

### Основные сущности

#### `users` (Пользователи)
Центральная таблица с данными клиентов.
*   `user_id`: Уникальный идентификатор (Primary Key).
*   `username`, `email`: Учетные данные.
*   `birth_date`: Дата рождения (используется для проверки возрастных ограничений).
*   `balance`: Текущий счет пользователя (используется для оплаты подписок).
*   `registration_date`: Дата создания аккаунта.
*   `last_activity`: Время последнего входа (с учетом часового пояса).

#### `movies` (Фильмы)
Каталог контента.
*   `movie_id`: Уникальный идентификатор (Primary Key).
*   `title`: Название фильма.
*   `genre_id`: Ссылка на жанр (Foreign Key).
*   `release_year`, `duration_min`: Метаданные (год, длительность).
*   `rating`: Рейтинг фильма (например, с IMDb).
*   `min_age`: Возрастное ограничение (0, 6, 12, 16, 18).
*   `is_available`: Флаг доступности (доступен фильм для просмотра или в архиве).

#### `genres` (Жанры)
Справочник жанров.
*   `genre_id`: Уникальный идентификатор.
*   `name`: Название жанра (Комедия, Драма и т.д.).
*   `description`: Описание жанра.

### Бизнес-логика и операции

#### `subscriptions` (Подписки)
История подписок пользователей. Позволяет отслеживать активные и истекшие тарифы.
*   `subscription_id`: Уникальный идентификатор.
*   `user_id`: Ссылка на пользователя.
*   `plan`: Тарифный план ('basic', 'premium', 'family').
*   `start_date`, `end_date`: Период действия.
*   `status`: Текущий статус ('active', 'cancelled', 'expired').

#### `payments` (Платежи)
Журнал финансовых операций.
*   `payment_id`: Уникальный идентификатор.
*   `user_id`: Кто платил.
*   `amount`: Сумма.
*   `status`: Статус транзакции ('success', 'failed').
*   `description`: Назначение платежа.

#### `views` (Просмотры)
Факт просмотра фильма пользователем.
*   `view_id`: Уникальный идентификатор.
*   `user_id`, `movie_id`: Кто смотрел и что смотрел.
*   `watch_date`: Дата и время начала просмотра.
*   `watched_min`: Сколько минут просмотрено (позволяет вычислять "досматриваемость").
*   `device_type`: Устройство (TV, Mobile, Desktop).

#### `reviews` (Отзывы)
Обратная связь от пользователей.
*   `review_id`: Уникальный идентификатор.
*   `user_rating`: Оценка пользователя (1-10).
*   `review_text`: Текст отзыва.

### Служебные таблицы

#### `audit_logs` (Аудит)
Таблица для триггеров. Хранит историю изменений данных.
*   `table_name`: В какой таблице произошло изменение.
*   `operation_type`: Тип операции (INSERT, UPDATE, DELETE).
*   `old_value`, `new_value`: Данные до и после изменения.
*   `changed_by`: Имя системного пользователя, выполнившего действие.

## 3. Схема связей (ER-Diagram)

Все связи в базе данных построены по принципу **Один-ко-Многим (1:N)**.

1.  **users -> subscriptions**
    *   Один пользователь может иметь *много* записей о подписках (история).
2.  **users -> payments**
    *   Один пользователь совершает *много* платежей.
3.  **users -> views**
    *   Один пользователь может посмотреть *много* фильмов.
4.  **movies -> views**
    *   Один фильм может быть просмотрен *много* раз разными пользователями.
5.  **users -> reviews**
    *   Один пользователь может оставить *много* отзывов.
6.  **movies -> reviews**
    *   У одного фильма может быть *много* отзывов.
7.  **genres -> movies**
    *   Один жанр присваивается *многим* фильмам.

### Типы данных (Ключевые особенности)

*   **MSSQL vs PostgreSQL:** БД представлена в двух версиях.
    *   В MSSQL используются `NVARCHAR` (Unicode), `IDENTITY` (автоинкремент), `DATETIMEOFFSET` (время с зоной).
    *   В PostgreSQL используются `VARCHAR`, `SERIAL`, `TIMESTAMPTZ`.
*   **Временные метки:** Используются типы с поддержкой часовых поясов для корректной работы глобального сервиса.
*   **JSON/Text:** Поля для отзывов и аудита поддерживают хранение больших объемов текста.
