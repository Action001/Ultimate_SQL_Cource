# Задания к Модулю 8: Автоматизация и Обслуживание

## Задание 8.1. Views
1.  **Каталог для пользователей:** Создайте представление `v_AvailableMovies`, которое показывает только доступные фильмы (`is_available = 1`) с названиями их жанров.
2.  **Аналитика:** Создайте представление `v_UserStats`, которое выводит: Имя пользователя, Количество просмотров, Общая сумма потраченных денег.

## Задание 8.2. Индексы
1.  **Поиск:** Представьте, что пользователи часто ищут фильмы по году выпуска. Создайте индекс на поле `release_year` в таблице `movies`.
2.  **Анализ:** (Устно) На какие еще поля в нашей БД стоило бы повесить индексы, учитывая наши частые JOIN-ы по `user_id` и `movie_id`? (Подсказка: посмотрите на внешние ключи).

## Задание 8.3. Jobs (Практика)

### Вариант А: Эмуляция (Скрипты)
*Если у вас нет прав администратора или не настроен Agent/pg_cron.*

1.  **Чистка:** Напишите SQL-скрипт (тело шага джоба), который удаляет из таблицы `audit_logs` записи старше 1 года.
2.  **Бонус:** Напишите логику начисления бонусов именинникам: найти пользователей, у которых сегодня День Рождения, и увеличить их `balance` на 100.

### Вариант Б: Hardcore Mode (Реализация)
*Только если вы работаете под sa/postgres и у вас запущен SQL Agent / установлен pg_cron.*

1.  **MSSQL:** Используя системные процедуры `sp_add_job`... (см. теорию), создайте джоб `WeeklyReport`, который раз в неделю запускает тяжелый SELECT (например, подсчет общей выручки за все время) и результат... ну, допустим, пока просто выполняет его. (В реальности мы бы отправляли email).
2.  **PostgreSQL:** Используя `pg_cron`, запланируйте ежеминутное обновление материализованного представления (или просто запись текущего времени в какую-нибудь таблицу-лог), чтобы проверить, что планировщик работает. Затем удалите задачу через `cron.unschedule`.
