# Теория к Модулю 4: Объединение таблиц (JOIN)

Реляционные базы данных хранят данные в разных таблицах. `JOIN` позволяет собирать их воедино.

## 4.1. Типы объединений

*   **INNER JOIN** (или просто `JOIN`): Возвращает только те строки, для которых нашлось совпадение в обеих таблицах. "Пересечение кругов".
*   **LEFT JOIN**: Возвращает ВСЕ строки из левой таблицы + совпадения из правой. Если совпадения нет, справа будет `NULL`.
*   **RIGHT JOIN**: То же самое, но сохраняются все строки правой таблицы.
*   **FULL JOIN**: Возвращает все строки из обеих таблиц (сопоставленные + несопоставленные с NULL).

**Синтаксис:**
```sql
SELECT t1.col, t2.col
FROM table1 AS t1
JOIN table2 AS t2 ON t1.id = t2.ref_id;
```

## 4.2. Фильтрация в JOIN (ON vs WHERE)

Это критически важный нюанс при работе с `LEFT JOIN`.

### Фильтрация в ON (Правильно для сохранения строк левой таблицы)
Условие применяется **в момент соединения**. Если строка справа не подходит под условие, слева данные остаются, а справа подставляется `NULL`.
```sql
-- Покажет ВСЕХ пользователей.
-- Если подписка не активна, в поле plan будет NULL.
SELECT u.username, s.plan
FROM users u
LEFT JOIN subscriptions s ON u.id = s.user_id AND s.status = 'active';
```

### Фильтрация в WHERE (Превращает LEFT JOIN в INNER JOIN)
Условие применяется **после соединения** ко всему результату. Строки с `NULL` (где подписки не нашлось) не пройдут проверку `NULL = 'active'` и будут удалены.
```sql
-- Покажет ТОЛЬКО пользователей с активной подпиской.
-- Пользователи без подписки исчезнут из выборки.
SELECT u.username, s.plan
FROM users u
LEFT JOIN subscriptions s ON u.id = s.user_id
WHERE s.status = 'active';
```

## 4.3. UNION

Объединение *результатов* двух запросов (склеивание "вертикально").
*   `UNION` — удаляет дубликаты.
*   `UNION ALL` — оставляет все строки (быстрее).
*   Важно: Количество и типы столбцов в обоих запросах должны совпадать.
